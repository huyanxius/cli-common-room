# 统一终端工作区架构

Common Room 在一个 Node.js 进程中承载终端界面与房间协调。Claude Code 与 Codex 是独立原生子进程，拥有自己的上下文、工具、认证和记忆。应用不直连模型接口、不复制凭据，也不把原生窗口跳转作为功能接入。

```text
bin/common-room.mjs → main.ts
                         │
               terminal/workspace.ts
                 │               │
           room/live.ts      storage/archive.ts
             │      │
      Claude SDK   Codex app-server
             │      │
         本机原生 CLI 进程
```

## 业务到模块

| 模块 | 实际职责 |
| --- | --- |
| `src/terminal/workspace.ts` | 生命周期、成员选择、消息流、命令派发、审批与恢复入口 |
| `src/terminal/screen.ts` | 按终端尺寸生成画面与输入光标位置，保留固定输入区 |
| `src/terminal/editor.ts`、`input.ts`、`text.ts` | grapheme 编辑、历史、粘贴分流、中文宽度与控制字符过滤 |
| `src/terminal/commands.ts`、`metrics.ts` | 应用命令菜单、原生目录合并、token 与额度格式 |
| `src/room/conversation.ts`、`telemetry.ts` | 成员会话、交互、命令目录与真实指标的共享契约 |
| `src/room/context.ts` | 从同一群历史截止点生成不可变的增量交付计划 |
| `src/room/live.ts` | 连接、群历史、交付位置、依次执行、取消与不确定状态 |
| `src/adapters/claude/` | 调用指定本机程序的官方 SDK、事件映射、工具授权与原生命令 |
| `src/adapters/codex/` | app-server 线程、轮次、命令、审批、用量与额度适配 |
| `src/runtime/native-auth.ts` | 调用原生登录与只读状态检测，控制子进程取消，不保存认证数据 |
| `src/storage/setup.ts` | 保存程序路径、成员与认证来源偏好；按配置目录隔离 |
| `src/terminal/setup.ts`、`queue.ts`、`tools.ts` | 配置页、接收者固定的消息队列、结构化工具呈现 |
| `src/runtime/stdio-rpc.ts` | JSON 行协议、请求关联、超时、连接关闭及自有子进程清理 |
| `src/runtime/workspace.ts` | 只读 Git 状态和差异，使用参数数组执行 |
| `src/storage/archive.ts` | 工作区隔离、本机房间存档、原子替换与恢复锁 |

原先的 `room/service.ts` 与 `room/agent.ts` 是无副作用交付规划的骨架接口；当前运行入口通过 `ConversationRoom` 执行会话，不将骨架里的不可用注册表当成实时连接状态。后续替换这些接口时不能改变 `context.ts` 的交付约束。

## 一轮消息如何执行

1. 用户用 `/to` 明确指定接收者。应用先确保所选成员全部连接成功，随后保存用户消息。
2. `planDeliveries` 冻结同一个群历史截止点，选出各成员交付位置之后的消息，排除该成员已经生成的回答。
3. 开始每位成员前先将其交付标记为未知并落盘，再调用原生会话。另一成员的历史回答带来源说明，不构成用户授权。
4. 双方依次运行同一份冻结快照，避免同时修改工作树或争抢审批输入。某成员本轮生成的回答只在下一轮交付。
5. 收到原生终止结果后推进交付位置；只有完整成功的回答进入群历史。取消停止后续成员，不回滚工具动作。

应用不宣称跨系统 exactly-once。发送前落盘、发送后断线或原生结果无法确认，都可能留下未知状态。恢复不会自动重发，也不会把已有成员回复绑定到一个伪造的新会话。

## 原生交互与命令

Claude 使用持续的异步输入流保留同一个本机进程，加载 user、project、local 设置以及原生系统提示。SDK 指向 PATH 或启动参数指定的 CLI，避免无意切换到 SDK 附带版本。`supportedCommands` 提供可执行目录；模型、MCP 与订阅额度使用结构化接口，其余目录命令送入原生命令解析器。

Codex 使用 `initialize`、`thread/start` 或 `thread/resume`，每个会话只允许一个活动轮次。开始响应前的通知先缓存，随后按 threadId 和 turnId 过滤。审查使用 `review/start`，压缩等待对应完成事件。模型、权限、推理强度与计划模式通过原生参数生效，不改写成普通提示词。

命令和消息分开派发。未知 `/` 命令明确拒绝；成员命令不能对双方模糊执行。原生终端专属命令没有统一透传接口，新增命令需按本机协议映射与验证，不复制一个同名空壳。应用保留房间级的新建、恢复、成员选择与退出语义，具体清单见 README。

审批绑定原生请求及取消信号。界面清空当前输入焦点、保存草稿，再显示成员名称、操作详情与明确选项；没有默认允许。答案回传前再次校验存活状态。Claude AskUserQuestion 按问题映射回答；Codex 问题按 ID 回传。秘密输入只渲染掩码。未实现的原生请求停止并报告错误，不降级成自动授权。

## 指标与终端行为

模型、权限、tokens 和订阅额度只来自原生事件或查询结果。额度按返回的窗口时长标识，300 分钟为 5h，10080 分钟为 7d；不假设 primary 必然是 5h。独立计量桶分别标名。数据缺失显示未知或未提供；token 使用与订阅限额不能相互推导。

界面使用终端默认前景与背景，Codex 紫色、Claude 橙色只作为强调。按行更新避免整屏反复清空；历史换行结果缓存。中文、emoji 和组合字符按 grapheme 处理，再计算终端列宽。不把原生文本作为 ANSI 控制序列执行。

输入启用 bracketed paste，将粘贴中的换行与确认键分开；审批同样要求再次按确认键。尺寸变化重算布局。退出在 finally 中关闭自有会话、释放档案锁，恢复光标、粘贴模式、替代屏幕和终端输入模式。

## 本机保存与恢复

档案位于 XDG state 目录，工作目录与原生配置目录参与命名空间。记录包含群消息、成员原生会话 ID、交付位置和未知状态。写入临时文件后原子替换；目录 700、文件 600。模型凭据、原生数据库与私人历史不复制进档案。

恢复先校验结构和所属工作区，再取得档案锁。存活进程占用的房间不能二次打开；已退出进程的锁可回收。恢复时沿用两侧原生会话 ID，任一失败就明确报错，不用新线程冒充原会话。本机锁仅覆盖 Common Room 入口，不能控制用户另外打开的原生 CLI。

普通操作请求超时会关闭连接并报告执行结果未知。纯额度查询超时只结束查询，不杀掉仍可使用的聊天连接。协议夹具、业务测试与 PTY 测试覆盖这些边界；真实 CLI 验证单独进行，不进入 CI，不保存截图。

## 配置、打断与输入队列

首次进入配置页，检测程序和本地认证；本地登录不代表模型请求一定成功。Claude 可选择本机登录或继承环境认证，SDK 会话和原生登录进程使用相同的显式环境。只有本机登录模式移除环境认证覆盖，其他配置保持继承。认证由原生程序存储，room 不读写认证文件。程序路径与来源变更后关闭旧连接，沿用已有会话引用重连；恢复失败明确报告。

工具事件携带原生 ID、名称、参数、结果与状态，界面合并更新同一工具记录，不从正文猜测完成。模型和思考强度列表来自原生元数据；选择后调用原生参数接口，Claude 的思考强度使用原生命令解析器。

Esc 通过 Codex `turn/interrupt` 或 Claude SDK `interrupt()` 打断，收到终止结果才允许正常继续。授权等待不默认批准；上下键明确选择后 Enter 确认。未获停止确认时关闭连接，保留交付未知保护。

运行时 Enter 加入本地待发送队列，记录提交时的接收者。队列不自动追加到当前原生轮次，也不冒充原生 steer。上一轮成功后依次派发；取消或失败暂停旧队列，用户仍能明确发起新指令。队列仅保存在内存中，退出不恢复未发送内容；`/queue` 可继续、撤回或清空。

终端解析器分开处理按键、bracketed paste 和 SGR 滚轮报告，独立 Esc 不被粘贴前缀吞掉。阅读历史时保持位置，按行刷新活动指示，避免整屏闪烁。退出恢复鼠标、粘贴、光标与替代屏幕状态。
